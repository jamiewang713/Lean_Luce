# Luce permutations in Lean

This project formalizes the paper **Fixed Points and Short Cycles of Luce
Permutations: Poisson Limits and Power-Law Endpoint Singularities** in Lean 4
with mathlib. A Luce permutation is generated by repeatedly choosing a remaining
label with probability proportional to its positive weight. Equivalently, one
can order independent exponential clocks with those rates.

The paper studies fixed points and short cycles in this model:

- **Finite-mean profiles:** fixed points converge to an inhomogeneous Poisson
  process, and counts of finitely many cycle lengths converge jointly to
  independent Poisson variables.
- **Power-law endpoints:** cycle means diverge, joint Gaussian limits emerge,
  and cycles concentrate on logarithmic distance scales near the endpoints.
- **The critical pole:** fixed-point counts have a Gaussian limit after
  centering by `log(log n)` and scaling by its square root, while each fixed
  longer cycle length has bounded mean.
- **Independent-clock extensions:** a general tail estimate applies beyond
  exponential clocks, with additional results for common-shape Gamma clocks.

Section 6 has seven subsections:

1. **6.1 — Population estimates for sampled profiles:** transforms, quantiles,
   and deterministic weight bounds.
2. **6.2 — Joint insertion estimates:** insertion moments, domination, local
   laws, and a density envelope.
3. **6.3 — Cycle bounds and logarithmic traces:** root and excursion bounds
   and ideal trace asymptotics.
4. **6.4 — Mixed factorial moments:** overlaps, nearby ranks, and core moments.
5. **6.5 — Power-law CLTs and localization:** joint and spatial Gaussian limits.
6. **6.6 — The critical pole:** predictable fixed-point estimates and longer
   cycle bounds.
7. **6.7 — The sampling grid and Sukhatme weights:** the interior-grid extension
   and the specialization stated as Corollary 1.9.

## Repository structure and naming

- **[Luce/Sections1To7.lean](Luce/Sections1To7.lean)** is the whole-project
  import entry point: use `import Luce.Sections1To7`.
- **[Luce/](Luce/)** contains the formalization. Each file name includes its
  paper section: for example, `Section2PoissonCriterion.lean` or
  `Section4RankIntegral.lean`. Shared helpers carry the section whose argument
  they support. `Section65*` denotes subsection **6.5**.
- **[audit/](audit/)** contains standalone statement checks, axiom inspections,
  verification scripts, and historical evidence. Audit file names also include
  a section; `Sections1To7*` covers the whole project, and `Section66*` covers
  subsection **6.6**.
- **[proposals/](proposals/)** contains recorded statement proposals. A proposed
  proposition is distinct from a proved theorem.
- **[docs/](docs/)** contains detailed statement mappings, assumption records,
  and verification reports. Dated progress reports describe their own snapshots.
- **[lakefile.toml](lakefile.toml)**, **[lean-toolchain](lean-toolchain)**, and
  **[lake-manifest.json](lake-manifest.json)** pin the build and dependencies.
  `.lake/` holds downloaded dependencies and generated build files.

The [rename index](docs/module-renames.md) maps the former file names to the
section-based names. Public mathematical names remain unchanged: for example,
module `Luce.Section1Sukhatme` contains theorem `Luce.Sukhatme.corollary19`.
Historical logs and frozen hash baselines preserve the paths and contents of
the revisions they checked.

## Formalization coverage

The formalization includes checked statements for the five main theorems
**1.3, 1.4, 1.6, 1.7, and 1.8**, the Sukhatme corollary **1.9**, the Section 4
slow-label and exceptional-shell refinements, the interior-grid extension, and
the independent-clock tail proposition **7.1**. The final statement checks
compare the proved conclusions with separately recorded contracts. A successful
build checks the Lean proofs; manuscript correspondence is documented separately.

## Build and inspect

The project pins **Lean 4.33.1** and **mathlib v4.33.1**. With Elan installed,
run from the repository root:

```powershell
lake exe cache get
lake build
```

The first command obtains mathlib's precompiled cache. For subsequent changes,
`lake build` is sufficient. The default build checks every production module in
`Luce/`, including the whole-project entry point.

To limit memory use during a full rebuild in PowerShell, first run
`$env:LEAN_NUM_THREADS = '2'`.

Standalone audits and proposals can be checked after the build, for example:

```powershell
lake env lean audit/Section1Sukhatme.lean
lake env lean audit/Section4Exceptional.lean
lake env lean audit/Sections1To7AllProvedStatements.lean
```

For interactive proof development, open this repository in VS Code with the
Lean 4 extension (`leanprover.lean4`). Elan selects the pinned toolchain from
`lean-toolchain`.
